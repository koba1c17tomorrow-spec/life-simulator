# P1-2 人生ログと世界履歴の境界

対象は新たに生じるNPC事実の公開経路。PCの知識を完全に模擬する情報伝播・NPC自律意思決定は実装しない。旧ログの内容を削除・再分類していない。

## 実装した経路

- `socialMonth` / `npcMonth` は種類・人物ID・構造化data・visibilityを持つ `NpcFact` を必須の第2引数として通知する。既存の文字列はdata.textとして保存するが、公開判定に文章の内容・正規表現・名前の一致を使わない。
- `engine` はこの通知をPCのjournalへ直接渡さず、`recordNpcFact` に渡す。まずP0-3のworldHistoryへ記録する。
- `learnWorldEvent` が公開条件を確認し、pcKnowledgeへ知った月と経路を保存してからjournalへ一度だけ記録する。人生ログは任意のworldEventIdで元の事実を参照する。
- `history` と `timeline` は引き続きPC向けで、worldHistoryを画面で一覧表示しない。NPCの事実を知った後も、その発生月自体を書き換えない。

## 最小公開ルール

| 種別 | 条件と扱い |
|---|---|
| 直接経験 | PCが人物ID列に含まれるparticipantsの事実。出会い・自然な交流・再会は従来の経験としてPCへ記録 |
| 公知 | 発生側が明示的にpublicを付けた事実のみ。APIと検証を用意したが、新たな社会事件の生成は今回実装しない |
| 会話での報告 | プレイヤーが生存する相手に「じっくり話す」（talk）を実行したとき、相手が当事者に含まれる未公開の事実をreportedとして知る。無関係な他人/故人を伝達者にできない。spendだけで一括公開しない |
| 死亡通知 | 遠方フラグのない家族、または死亡時点でのPC交際相手/配偶者の死亡をreportedとして通知する。家族の所在地の精密なモデルがないため、これは明示的な通知ルールであり、伝播を計算したものではない |
| その他のNPC事実 | 就職・失業・病状・転居・NPC同士の交際/結婚/出生/関係はprivateが既定。単に知人であることや文章にPC名が含まれることでは人生ログに流さない |

reported/publicには「知らせ」を付け、知った月が発生月と異なる場合は発生月も添える。会話で自分の事情を必ず共有することの細かな意思決定・拒否や、噂/秘密の伝播はP3以降の課題。会話の既存コストや関係値の増減を変えない。

PC自身の選択は引き続き直接経験で、P0-3のpc.choiceに紐づけて記録する。PCの健康、購入、就学、仕事等の既存の直接ログ経路は保持し、全イベントエンジンを作り替えない。

## 保存と互換性

worldHistoryは任意。欠落した過去を生成せず、旧history/timelineはそのまま保持する。過去のPCの知識を文章から完全に復元できないため、旧文章を新しい「公開済み」の事実へ変換しない。過去に混在してしまったNPCログが消えるわけではない。公開境界は新しく記録する事実から適用する。

pcKnowledgeは同じworldEventの公開済みマーカーであり、保存再開・同月pendingの再advance・重複公開呼出しでは新規PCログを生成しない。PCログの1500件上限後もマーカーを消さず、再通知しない。公開後に元の発生月・内部事実を上書きしない。

JSONエクスポートには非公開の内部状態も含む。プレイ画面での知識境界であり、保存ファイルの暗号化や改ざん防止を提供するものではない。また、既存の人物パネルで人物の状態を表示する機能は今回全面刷新していない。NPC内心の表示体系はP3-1/P4-3の担当である。

## 検証と残課題

`tests/npcKnowledge.test.ts`：非公開とPC名入り文章、直接経験、公知、遅れた報告、無関係/死亡した伝達者の拒否、同一事実の非重複、実月次の遠方NPC死亡、家族通知、pending保存、旧履歴保護を検証。

`browser-tests/knowledge.spec.ts`：modern/coastalで遠方NPCの死亡が内部保存に残り、画面の人生記録には出ず、再読込後も漏れないことを検証。P0-1/P0-2の再現・保存・3スロット・遅延結果の回帰を維持する。

履歴は自動削除しないため、長期の保存サイズ・処理量は残る課題。全コンテンツの情報公開やすべての伝達経路をモデル化したわけではない。新たなNPC更新経路を追加するときは、必ずNpcFact相当の公開根拠を持たせる。バランス/経済/職業/成長の係数・乱数消費は変更していない。

## P3-2更新

NPC目標はprivateかつdisclosable:falseで保存し、talkの一括報告でも公開しない。NPCの返答/拒否/PCとの交流/別離はparticipantsとして直接経験を記録。通常人物画面はNPCの新しい生活実状態を直接表示せず、導入時に既に表示されていた情報と、その後pcKnowledgeを得た事実の投影を用いる。導入前の履歴で現在表示を巻き戻さない。PCの共有児童参照は既知の家庭情報として利用する。潜在的な感情数値や内部目標は表示しない。JSON内部状態の秘匿性とは区別する。
