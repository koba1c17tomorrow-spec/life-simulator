# P3-3 更新段階と計測基盤（実遅延は保留）

## 実装範囲

npcTiers version1にActive/Dormant/Archived候補、観測開始月、最終観測月、人物ごとの最終詳細更新月を保存する。updatesは常にfull。**Dormant候補も毎月従来どおり詳細更新する。今回、実際の遅延更新/補完/高速化は有効にしていない。P3-3全体の完了ではない。**

Active候補は近くの家族/PC交際配偶者、近くてPC側親密さ50以上、または直近6月の接触がある人物。その他の生存者はDormant候補、死亡者はArchived。内部分類を新しいPC情報として公開しない。

旧セーブのlastDetailedMonthはロードで補完せず、新しい分類を初めて作る時点でも不明ならnull。実際に生存者を詳細更新した期間だけ、呼出し側が更新対象IDを渡して現在月を記録する。死亡月に処理された人物はその月を記録し、以後Archivedの時計を進めない。既に死亡した旧人物の過去時刻は推定しない。人物・死亡月・関係・履歴を削除しない。再会後の分類更新は詳細更新の再実行や時計の補完を行わない。

## 切替を保留する理由

旧NPC健康/死亡/制度は単一seedを、新しい相互行動は共有npcRelationsを使う。NPC同士の相手の時間消費、婚姻・死別、社会接触に月内の依存がある。個別NPCの過去を後から処理すると他人物の乱数や関係の時系列が変わる。過去の乱数/相手状態は保存されておらず、独立に再生成した結果を同じ世界の履歴とする根拠が不足する。

このためユーザー指定の保留策を採用した。必要な追加設計は、人物別/期間別の乱数規則、対人行動の時系列調停、死亡をまたぐ補完、過去の事実と現在の知識の分離、大量seedでの分布/性能比較である。保留中に擬似catch-up APIを成功扱いで提供しない。

## 計測方法

`node scripts/npc-performance-study.mjs docs/measurements/p3-3-performance.json`

20/50/100 NPC、seed 42/7919/20261016で、従来の詳細更新と分類を付加したfull更新を各1200月測定する。専用NPCドライバーで状態コピー、旧NPC生活処理、新agency、世界履歴を含む。PC自身の健康・家計・イベントは実行しない（PC死亡で100年に満たなくなるため）。実ゲーム全体の100年実行時間ではない。

月平均/中央値/p90、1200月合計、時点別保存UTF-8バイト数/文字数、通常の再接触コストを記録する。実遅延の補完時間は未実装なのでnull。全員死亡後の月も含む。開始人口は閉じた合成コホートで、正規旧セーブfixtureとは区別する。分類を除く状態のSHA-256一致で、観測機能が状態・乱数・履歴を変えないことを比較する。保存の5,000,000文字上限や実行失敗を隠さず記録する。性能の固定合格しきい値は設けない。
