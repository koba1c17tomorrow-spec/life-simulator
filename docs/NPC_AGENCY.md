# P3-2 NPCの目標・判断

## 責務と切替

任意npcAgency version1を最初の新しい月または実際の誘いへの返答から開始する。旧人物を初期化せず、現在から観測する。人物の過去の生活費・財産・目標は生成しない。仕事の有無を資金制約の粗い代理とする。健康/死亡/教育/既存の結婚・出生は従来npcMonthが所有し、仕事/転居/新しい交流・交際形成/別離はagencyが所有。所有する人物について旧socialMonthの仕事・転居・自動接触、npcMonthの再就職・交際形成・離婚・年次交友の重複を止める。近親/未成年の恋愛を許さない。

## 時間・目標

全生存NPCに予算を設け、成人の自律判断では、健康/疲労、失業、家族志向、自由志向、対人関係からhealth/stability/family/independence/connectionを選ぶ。固定した筋書きではなく月の状態から再評価する。月720時間から睡眠240・家事60・休息60・就業160・子1人8・病気48を確保する。使える時間と実消費を保存し、同月再開でリセットしない。就職で新しい義務が増えれば残時間を減らすが、退職で確保済み時間を戻さない。未成年の自律行動と死亡者の新規agencyは生成しない。

求職16時間、休養24、交流8（相手にも8）、転居24、交際相談8、結婚/家族相談16を要する。PCとの交流はPCの同じ時間予算からも消費し、NPCからの交流はPCの自主行動枠を使わない。拒否された誘いはPCの試み2時間、NPC返答1時間（返答時間がない場合0）。技能は実際に会話できた8時間だけ成長。PCの健康・時間も実行前に検査する。

NPCは健康/義務/既存関係/自由志向等で誘い・交際・結婚・家族計画を拒否できる。PCからの親密さだけでは受諾を保証しない。NPC同士の交流は近隣の少人数の知人候補を用い、同一ペアを月内重複処理しない。関係悪化や生活方針により別離する。死亡者の人物/感情/過去参照は維持する。

## 乱数と知識

新判断はrandomStreams.npcRelationsを使用。他の3ストリームと従来seedは全面移行しない。既にストリームがあれば継続、なければ初回使用時の現在seedからcreateRandomStreamsで開始し、agency.startSeed/startMonthに導入境界を記録する。過去から復元したものではない。人物ID順で処理し、保存再開で同じ状態を消費する。旧NPC判断の廃止に伴う旧seedの消費順変更は意図した局所切替であり、過去版と同じ人生になるとは保証しない。

目標変更/私的生活/対人行動はNpcFact→worldHistoryを通す。内心に属する目標にはdisclosable:falseを付け、会話でも自動公開しない。PCとの実際の交流/拒否/別離はparticipantsとして直接経験を記録する。通常UIには目標や感情数値を渡さない。日常休息や不成立の求職はactor.lastActionに残し、重大な状態変化・新規関係・応対や関係段階の変化を世界履歴に残す。日常の反復交流はlastActionと関係状態に反映し、毎回同じ文章を人生ログへ追加しない。人物IDのソートは環境依存のlocaleを使わず文字列コード順で固定する。

通常人物画面では、導入直前に既に表示されていた生活情報/つながりをknownPeople/knownLinksとして保持し、その後はpcKnowledgeを得た出来事だけを投影する。過去の記憶を再構成するのではなく既存の公開情報を保持する。新しい私的就職/病状/婚姻等を実状態から直接表示しない。プロフィールの元情報は削除しない。

回帰で、24か月未接触をPC候補から永久除外する条件が関係の再形成を妨げ、100人生の子あり4件となることを確認した。この一方通行の条件を廃止し、既知の人物なら再接触候補とする。connection/familyの交流機会は従来の自然接触と同じ月0.12、その他0.08とし、quietは同席一辺倒でなく会話を選ぶ。健康・時間・相手の意向は引き続き必要。回帰しきい値の緩和で通さない。

長期回帰の180秒制限に達したため、操作の所有境界を確認して不要な複製を除いた。autoResolveの一時オブジェクトはseedだけを変更し、chooseは従来どおり入力を深く複製する。choose内から月処理へ再開するときは既に専有する複製を私有関数に渡し、再び全履歴を複製しない。public advanceMonthは必ず入力を深く複製する。返却状態の入れ子を変更しても入力が変わらない回帰を追加。乱数消費・分岐・期待値・テスト時間制限は変えない。

PCと共有する子は既存parentIdsから現在の家庭制約へ参照し、NPCの旧childCountを書き換えない。通常画面でもPC自身が知る共通の子の数を反映する。既に公開した情報の投影には、導入時の月とworldHistory.nextIdを保存し、それより古い通知で現在の既存表示を上書きしない。

NPC IDを辞書として扱う箇所は自身のプロパティだけを参照する。toString等の通常の独自IDは保持し、prototype/constructor/__proto__とPC用playerはNPCの予約IDとして拒否する。正規生成された既存ID/fixtureへの変更はない。拒否時の元保存保護は既存経路を維持する。

共有子と既存childCountの重複対応は推定せず、大きい方を現在の家庭制約/PC既知情報の下限として使う。NPC同士の子どもの個人IDを網羅する世帯モデルは未実装。目標・経済は既存タグに基づく粗いモデルであり、完全なNPC家計・職能モデルを実装済みとはしない。
