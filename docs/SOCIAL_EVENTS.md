# P4-2 社会イベント

任意societyEvents.version:1。月の開始時、社会6軸更新直後に1回試行し、人物の健康/NPC/経済/選択処理は既存順序のまま。その後にpendingを作る人物イベントを優先して処理する。既存pending中は月が進まないため社会も再実行しない。社会イベントは非選択型でqueue/pending/scheduledを操作せず、同月連鎖もしない。

定義はsrc/societyEvents.tsのSOCIAL_EVENTS。ID、random/conditional/history、条件、cooldown、効果、public/private、現代/ファンタジー文章を持つ。ランダムな供給停滞（economy -2）、公衆衛生48未満の清掃（+1）、安定48未満の非公開内部協議（+0.5）、先の停滞から3〜24か月の回復（economy +1）、導入後のcommunity_project参加選択から24か月以上の成果（tolerance/mobility +0.5）を実装。分類は発生理由の違いであり、条件型/履歴型も必ず起きるのではない。

前回の社会事件から12か月、同じIDは36か月（地域成果120か月）以上空ける。適格候補があれば月4%で試行し候補から一様選択、最大1件。率は暫定の小規模実装値で、現実の統計ではない。平均回帰は別に毎月進み、何も起きない月を許容。社会専用worldSociety継続値だけを使用し、旧seed/NPCストリームを消費しない。

履歴はworldHistoryのsociety.IDへ記録。dataにdefinitionId/category/text/reason/causes（実在するworld-ID）/effects（clamp後の実変化）を保持。最新原因を小さなlatest辞書に保持し、毎月全履歴を走査しない。旧ログを解析して架空の原因を作らない。community_projectの実選択だけを導入後に捕捉する。無限因果ループを作る定義はなく、回復は同じ原因につき1回。

社会への効果は小幅でPCの資産や健康を直接書き換えない。NPCとPCの誘いは共通societyRestrictionを参照し、safety<20のときspend（外出）だけ断る。talkは可能。実際の制約発生時の行動結果変化は意図した接続で、乱数の追加消費ではない。雇用/収入/健康の新倍率は未接続。既存初期値周辺での旧ゲーム結果は維持するが、新社会ルール下での危機時まで旧結果の一致は保証しない。

publicは公表可能の意味。自動でPC既知にしない。private協議はニュースでも出さない。P4-3の明示的な確認で初めてpcKnowledge/人生ログへ反映し、発生月と知得月を保存。未読社会履歴の増加で既存world-Nの番号はずれるが、識別子の採番規則は維持し、人物の確率判定には利用しない。

旧保存は次の月から導入。キー/外形/スロットは無変更。lastTick、最後の発生月、定義ID、原因参照を検査して拒否し、入力を変更しない。fantasyは社会設定と文章のユニット検証まで。プレイ可能世界はmodern/coastalのみで、ファンタジーの人物/データ/保存/ブラウザ通し検証はP5のワールド試作待ち。
