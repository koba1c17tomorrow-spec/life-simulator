# P5-3 街と工房の人生

新しい独立worldId=fantasy。新規ゲームの世界/種族選択から開始する。冒険や戦闘は一切必須ではなく、農民（既定）、職人、商人、学者、市民の手仕事が生活を支える。種族はhuman/elf（人間/長命の民）、寿命上限900/1440か月。現代の100歳上限/入試/年金/円経済を名前だけ置換していない。

fantasy.tsはfantasyだけの小さな月次方針。72か月から寺子屋・徒弟教育、192か月から就業、銀貨の月収/生活費、種族別のPC/NPC健康・寿命を実行。各職の収入35〜70、基本生活費30（子ども1人あたり+3）、幼少期の扶養8/支出8。暫定の箱庭用数値で現実や歴史の統計ではない。公衆衛生による小健康補正をPC/NPCへ共通適用し、景気をPC収入の小補正（0..100で0.955..1.055倍）に接続。NPCにはまだ貨幣の家計台帳がないため所得分布モデルは未実装。種族寿命は上限であり、健康0でも死亡する。出生時の親/近所の3人を種族付きで生成し、死亡月固定とArchived時計を共通実装で保持する。

共通の社会6軸とfantasy社会事件、NPCの目標/交流/拒否/関係形成、720時間予算、技能、シナリオ、知識公開、保存を利用。現代の入試/職業求人/家計の経路はfantasyで動かさず、職業と家計の既存タブには小さなfantasyパネルを出す。現代/海辺の画面配置は変えず、シナリオは記録画面の閉じたdetailsへ追加。GUI全体の設計はIssue #9待ち。

生活魔法は72か月から任意の8時間練習、月1自主行動枠と同じ時間/健康条件を使う。習熟0..100と実練習時間を保存し、工房の依頼で魔法を使う選択肢の条件になる。手仕事だけでも依頼を終えられ、魔法や冒険を強制しない。工房シナリオは道具準備→手仕事/魔法/撤退、費用・成功失敗・礼・借りた道具の返却を共通状態機械で処理する。現代/海辺には仕事と家の用事（相談/単独計画→仕事/家庭優先）を追加。自動と手動、途中保存、月待ちに対応。

ルール正本はsrc/fantasyRules.json。public/worlds/fantasy/{manifest,events,rules}.jsonをサブパスで取得。公開rulesは正本の配布コピーで、loadWorldは同一内容を検査して異なるルールの混在を拒否する。Viteのpublic直接import警告を避けるため正本と配布を分け、単体で一致を検証する。JS同梱の正本とJSON3本は既存PWA globでprecacheされる。世界ID/種族/魔法/生業とシーンはv1の任意拡張として保存。未来版/不正な種族/魔法/人物種族は拒否する。既存modern/coastalの保存をfantasyへ強制変換しない。

未実装: 多地域、戦闘/ダンジョン、詳細な魔法体系、種族別の成人年齢、fantasyの結婚/出産/世代交代/職業資格/老後制度/金融・買い物、NPC家計、統計較正。PCの旧円建て婚姻/求人/買い物APIはfantasyでは無効にし、単位混在を避ける。共通NPC自律行動の成人/就労判断には旧18歳/65歳などの閾値が残る。NPCの実遅延（Issue #7）は行わない。実行時AI/APIなし。

検証: tests/fantasy.test.ts（実就業と収支、900/1440か月の非冒険人生、魔法/シーン、保存/3スロット、非公開保護/版拒否）、browser-tests/scenariosWorlds.spec.ts（新規世界/種族選択、PC/スマホ、途中保存/手動/自動）、pages-tests/fantasy.spec.ts（本番サブパスでオフライン3JSON・新規開始・月進行・保存）。実機Safari/Android、WebKit実行可否はVALIDATIONへ分けて記録する。

公開のfantasy人物イベントは現在log型2本だけで、通常人生の選択イベントは増やしていない。分岐は共通シナリオで実装する。将来choice型JSONを追加する際は、fantasy月次方針へのpending/queue処理統合と保存回帰が必要。世界定義のデータ形が共通でも、全ての旧現代イベントをfantasyへそのまま流用できるとは主張しない。
