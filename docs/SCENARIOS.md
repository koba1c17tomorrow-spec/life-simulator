# P5-1 連続シナリオ

scenarios.version:1は任意。旧保存の読込で補完せず、実際の開始時だけ生成する。activeにはrun ID/定義ID/シーンID/状態/開始終了月/step/局所乱数/対象人物/選択履歴を保存。inventoryは導入後に取得した持ち物だけを保持する。過去の場面や所持品を推定しない。外側v1/キー/3スロットは維持。

開始は通常月の処理完了後、pending/queueが空で生存・年齢・体調・世界・12か月cooldown条件を満たすとき。runningでは月次/自主行動/交流/購入等を停止する。選択は公開されたPC能力/技能/PC側関係/持ち物/所持金/健康条件を検査し、1つの選択の時間・費用・効果を原子的に反映する。UI/APIはstep番号を渡し、古い選択の再送を無効にする。次のシーンへ遷移、成功/失敗/撤退で終了。終了結果はPC直接経験としてworldHistoryとjournalへ1回記録。途中経過も保存する。

時間は既存720時間/月と同じ単位。選択の所要時間が余剰時間を超える場合、部分課金せずwaiting-monthと未実行の意図を保存する。ここでのみ通常のadvanceMonthを許可し、既存の月次健康/社会/NPC/経済/選択/遅延効果を実行する。pendingは通常選択が優先、queueを消化し月次が終わってからrunningへ戻る。死亡/体調悪化では中断。次月に選択を再確認する。単一選択を月またぎで分割せず、月単位の義務で実行不能なら撤退可能。シーン内時間を月に追加せず、既存予算のactivitiesへ差し引く。

乱数は開始時の現在seedを既存events名前のFNV規則で分離し、run.randomStateからLCGを継続。既存seed/randomStreamsを消費しない。自動は実行可能な最初の選択を最大16段階進める（世界月を自動的に無限進行しない）。現在の定義は非循環で、長時間自動待ちは明示的な次月操作が必要。生のNPC内心/社会未確認事件は選択条件に使わず、PCの実体験だけを結果として表示する。

代表はtown-errand（段取り→窓口、準備メモと体調、PC技能による成功失敗、撤退）。汎用定義は費用/報酬/健康/関係/持ち物/技能成長と条件を扱う。P5-3で現代の日常シナリオとfantasy用シナリオ、最小限の操作パネルを追加する。

tests/scenarios.test.tsで旧fixture、排他、途中保存、手動/自動、時間不足/月境界、入力不変、stepによる再送拒否、局所乱数、撤退/不正保存を検証。未知の定義/シーン/版/不正な履歴/参照/時刻/数値は拒否する。定義変更を伴う将来版の移行は別途必要。

## P5-3 補足

現代/海辺のwork-and-homeとfantasyのguild-orderを追加。借用品は定義のtemporaryItemsに記載し、完了/失敗/撤退/中断で返却する。無時間の撤退はactivitiesへ0時間を入れない。終了runは次回開始時にarchiveへ移し、過去の選択履歴を消さない。UIはstepに加えてrun IDを送り、別runの古いクリックも拒否する。対象の死亡/体調変化は次月再開時に中断し、月次pending/遅延効果は従来どおり一回処理する。
