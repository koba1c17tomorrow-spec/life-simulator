# Life Simulator v3 ゲーム設計

この文書はP0-0で保存する**将来の確定仕様**であり、実装済み機能一覧ではない。現行は `2.0.0-beta.1`。P0-0ではゲーム・セーブ・依存関係・CI・公開設定を変更しない。実装順序は [ロードマップ](ROADMAP_V3.md)、検証基準は [受入条件](ACCEPTANCE_CRITERIA.md)、作業規則は [AGENTS.md](../AGENTS.md) を参照する。

## 1. 基本思想

出生から死亡までを月単位で体験する、文章中心のブラウザ人生シミュレーターとする。

- PC（プレイヤーの人物）は世界の中心ではなく、世界に生きる一人の人物である。
- 努力は成功を保証しないが、選択と経験は将来の可能性に影響する。
- 幸運、不運、失敗、事故、病気、死別、突然の死も起こり得る。
- 結果を公平にするのではなく、世界の仕組みに一貫性を持たせる。
- 統計的なリアリティを基礎に、人物の履歴や関係から物語性を生む。
- 平凡な人生を無理に波乱万丈にしない。重大な不幸を一定間隔で強制しない。
- プレイ中に生成AIや外部APIを呼び出さない。
- 乱数シードと操作履歴から可能な限り再現できる設計を維持する。

## 2. 人物モデル

| 層 | 内容 | 変化・公開方法 |
|---|---|---|
| 1 生得的な資質・適性 | 人物の生まれ持つ傾向 | 基本的に固定。プレイヤーには経験等を通して定性的・段階的に判明する |
| 2 基礎能力 | 多くの活動に共通する能力 | ゆっくり変化する。PCには数値表示する |
| 3 専門技能 | 分野ごとの熟練 | 練習・仕事・経験で成長する。PCには数値表示する |
| 4 経歴・経験・評判・資格 | 人物の履歴と社会的な評価 | 履歴として保持し、将来の判定に影響する |

技能成長は実際の活動時間、資質、訓練環境、疲労、健康、現在の熟練度に依存する。高レベルほど成長しにくくする。全員が高能力になる設計は避ける。能力の種類・範囲や成長式の係数は実装タスクで根拠と観測値を記録して決める。

## 3. 時間と行動

基本は1ターン＝1か月。毎月、継続的な「生活方針」と具体的な「重点行動」を選び、重点行動には強度を設定できる。

行動は成功を保証する命令ではなく、人物の意図である。健康、時間、資金、家庭、仕事、外部事件によって妨げられることがある。予定と実際の活動・中断理由を区別する。

行動時間の予算を設け、仕事・学習・交流・休息・家庭・趣味などを競合させる。月内の行動とシーン内の経過時間は同じ予算で扱い、同じ時間を二重に消費・付与しない。時間の内部単位や繰越の扱いはP2-2で定義する。

## 4. NPCと人間関係

NPCはPCから独立した性格、価値観、目標、生活、関係を持つ。

AからBへの感情とBからAへの感情は別々に保持する。基本は「好意」「信頼」「親密さ」「敬意」の4軸で、恋愛的魅力は別要素とする。交流による改善は保証しない。相性や状況によって改善、悪化、変化なしが起こる。

NPCはPCの誘いを断り、関係を解消し、PC以外の人物とも関係を形成できる。行動・婚姻・親子・死亡等の参照整合性を維持する。

| 更新段階 | 対象と処理 |
|---|---|
| Active | 近しい人物。毎月更新する |
| Dormant | 疎遠な人物。状態と最終更新時刻を保存し、必要時に経過期間を補完する |
| Archived | 死亡者など。死亡後の加齢・生活更新を行わない |

死亡年月を固定し、死亡時年齢は死亡年月と出生年月から計算する。現在年月を使って故人を加齢させない。死亡後に新しい就職・交流・出産等を発生させない。死別を知る時点と死亡した時点は区別できるようにする。

## 5. 社会と経済

初期実装は単一の箱庭社会とし、地域別シミュレーションは後回しにする。共通の社会状態は次の6軸とする。

1. 景気
2. 治安
3. 政治的安定
4. 社会的流動性
5. 公衆衛生
6. 社会的寛容性

平均回帰を伴う確率的変動、事件によるショック、人物の影響などで変化する。雇用、収入、健康、教育、事件発生などに影響させる。PCとNPCには原則同じ世界の法則を適用し、簡略化が必要なら範囲と影響を記録する。各軸の数値範囲・係数や地域の追加は未決定であり、現行の地域ラベルを地域別社会シミュレーションとみなさない。

## 6. イベントと情報表示

イベントには、純粋な偶然、現在の条件に依存する出来事、過去の行動や人物関係に由来する出来事の3系統を組み合わせる。重大な不幸を一定間隔で強制発生させる調整はしない。

選択前には状況と予測可能な手掛かりを文章で提示する。成功率や死亡確率などを安易に数値表示しない。選択後には結果パネルで、何が起こったか、何が変化したか、判明している因果関係を説明する。未知の因果やNPCの内心を事実として断定しない。

- PCの能力・技能：数値表示する。
- 健康・精神状態・疲労：内部状態に対応する正確な5段階と説明文を表示する。5段階の境界・名称は実装時に定義する。
- 未診断の病名：隠してよいが、現在の健康状態を偽らない。
- NPCの内心：正確な数値で公開せず、言動から推測できるようにする。
- PCの人生記録：PCが知り得る内容を保存・表示する。
- 内部の世界履歴：PCが知らない出来事も扱い、人生記録と分離する。デバッグ用の情報を通常画面へ漏らさない。

## 7. 連続シナリオ

面接、恋愛、政治、研究、ダンジョン探索などに共通利用できるシーンエンジンを設計する。シーン中は月次進行を一時停止して内部で時間を進め、経過時間を月の行動時間から差し引く。

技能・持ち物・人物関係に応じた選択肢、成功失敗の分岐、途中保存、手動・自動進行に対応する。再開や自動進行でも時間・費用・報酬を二重計上しない。結果は通常の人生シミュレーションの状態・履歴に反映する。具体的な状態機械・月境界の扱いはP5-1で定義する。

## 8. 複数ワールド

人物・時間・行動・関係・イベント・保存は共通エンジンとし、教育制度、職業、貨幣、種族、魔法、寿命、社会制度等は世界固有ルールに分離する。

現代ワールドの基盤整備後にファンタジーワールドを試作する。冒険者以外の人生を選べるものとし、冒険やダンジョン探索は任意の活動とする。既存の現代・海辺ワールドは保持する。新ワールドの追加を既存セーブの暗黙の変換やワールドの強制変更にしない。

## 9. 現行実装との違い（P0-0時点）

以下はソース確認による現状と将来仕様の区別であり、このタスクでの修正対象ではない。

| 領域 | 現行v2の状態・主な参照 | v3で行うこと |
|---|---|---|
| 人物・成長 | `src/engine.ts` のstatsとtraits、`balance.ts` 等。4層の独立した体系ではない | P2-1〜3で4層・活動時間依存の技能成長へ移行 |
| 行動 | 生活方針・個別交流・購入等。統一した月間時間予算・重点行動強度はない | P2-2で意図と実行結果を分ける |
| 関係 | `social.ts` のcloseness/trustと任意のromance。PCに紐づく関係値で、contactは値を加算する | P3-1〜2で方向別4軸・恋愛的魅力・拒否や悪化を扱う |
| NPC更新・死亡 | `relationships.ts` のnpcMonthは故人を除外するが、Personに死亡年月がなく、`main.tsx` の人物年齢は現在月から計算する。3段階更新はない | P1-1で死亡固定、P3-3で遅延更新 |
| 記録 | `journal.ts` のhistory/timelineへNPCの生活ログも入る。PCの知識での分離はない | P1-2でPC記録と世界履歴を分離 |
| 社会・経済 | 地域・家計・職種はあるが、共通の社会状態6軸はない | P1-3の暫定抑制後、P4-1で社会状態を導入 |
| イベント・表示 | 条件・フラグ・遅延結果は実装済み。健康/ストレスや採用率の数値表示があり、v3の5段階表示・結果パネルとは異なる | P4-2〜3で整理 |
| シーン | pendingによる月内の選択停止はあるが、汎用シーン時間管理・途中保存モデルではない | P5-1で共通化 |
| 世界 | modern/coastalのJSONを読み込むが制度は共有し、世界ルール分離やファンタジーは未実装 | P5-2〜3で分離・試作 |
| 保存・再現 | `version:1`、`life-sim-modern-v1`、3スロット、JSON入出力、正規化。seedは現在の乱数状態、birthSeedは出生入力。操作履歴による完全な再生基盤は未整備 | P0-2〜3で移行と履歴を設計。旧ルールと新版の結果一致は保証しない |
| 検証 | 長期100シード、単体・ブラウザ・Pages/PWAテストがある。既存の寿命・成長等のしきい値は現行回帰条件 | P0-1で基準を固定し、P6でv3の分布と体験を再評価 |

## 10. 未確定の実装詳細

具体的な型名、保存バージョン、乱数ストリーム分割、5段階の境界、時間単位、係数、分布の目標値、NPC段階の移行条件は今後の担当タスクで設計・検証する。ここにない数値や方式を確定済みとして扱わない。ゲームの基本思想・上記の仕様を変える場合はユーザーの判断を求める。
